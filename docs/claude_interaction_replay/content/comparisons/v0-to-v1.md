# v0 → v1：机制正确，不代表生产对象正确

| 判断维度 | v0 | v1 | 变化含义 |
|---|---|---|---|
| 核心问题 | LLM 知识生产机制如何可审计 | LLM Wiki 应覆盖哪些主题 | 从机制验证切到 topic 建设 |
| 生产单元 | 机制概念节点 | 主题枢纽节点 | 内容方向修正，但粒度仍然过大 |
| 来源处理 | 验证 provenance 和动态检索记录 | evidence matrix 支撑主题综合 | 来源开始服务覆盖框架 |
| 成功标准 | 文件合同与图机制跑通 | 主题覆盖和 QA 通过 | QA 更完整，但测错了生产目标 |
| 留给下一版的问题 | topic 错位 | 不是自底向上的原子知识卡 | v2 必须重定义生产单元 |

这次变化揭示了贯穿后续版本的一条原则：**工程机制的正确性（mechanism correctness）与知识产品的正确性（product correctness）必须分别验证。**
