# v1：把 LLM Wiki 做成八个主题枢纽

## 版本核心

v1 修正了 v0 的 topic 错位，围绕 LLM Wiki 构建 8 个自顶向下的主题节点：起源、定义、架构、工作流、与 RAG 的比较、治理风险、实现生态和评估证据。

## 相对 v0 的优化

- 保留 filesystem-backed、provenance、citation graph 和验证门禁。
- 从“知识库生产机制”切换到“LLM Wiki 本身”。
- 增加 coverage framework、evidence matrix、source gap review 和主题规划。
- 让最终 QA 同时检查主题覆盖、引用布局和影响队列。

## 关键决策

把候选主题作为生产单元，由来源观察和 evidence matrix 支撑综合型 hub page。这个决策能快速形成全景，但也把来源中的原子观察过早压缩为报告式叙事。

## 实际动作

完成 8 个已采用主题节点、8 个 KB 视图和 185 条引用边；当时的节点、卡片和脚注布局门禁均通过，`impact_queue_open=0`。

## 失败与纠偏

最终 QA 在当时通过，但它测量的是主题覆盖，而不是原子事实可靠性。主题成为了生产单元；知识卡更像综合报告，出处论证和控制面也过重。

## 如何触发 v2

用户重新定义了生产目标：不要继续扩建 hub skeleton，而要从来源中自底向上生产限定范围、可独立验证的知识卡。v1 因此被保留为注意力地图和失败证据，而不是继续演化的 active KB。
