# v2：把生产单元改成限定范围知识卡

## 版本核心

v2 否定了“先设计完整主题树，再填充内容”的默认路径。生产单元改为从来源中生长出的 scoped knowledge card；brain mailbox、主代理控制面和 provenance gate 用来约束生产、审计和恢复。

## 相对 v1 的优化

- 生产对象从 topic hub 改为来源支撑的 scoped card。
- taxonomy、cluster、hub 和主题覆盖退出当前循环目标。
- 主代理被限定为决策者；来源挖掘、写卡和审计交给有界 worker。
- 引入稳定 system prompt、task template、context isolation 和 sub-agent lifecycle。
- 把 card 正文与 provenance 过程文档分开，恢复可读的 zet card。

## 关键决策

知识卡可以具有依赖关系，也不必追求机械地“一句话一卡”。关键是 scope 可辨、知识含量足够，并能通过来源和 provenance 被做实。候选选择不能由主题覆盖或 hub 规划驱动。

## 实际动作

循环从 source mining 开始，经过 drafting、audit 和 adoption 反复迭代；每个 worker 交付都要有 marker、read log 和边界检查。过程中多次因为任务包、允许读取范围和审计输入不精确而暂停生产，修复稳定 prompt 后再恢复。

## 失败与纠偏

控制严谨但成本很高；大量循环时间耗在 worker 边界、delivery marker 和审计模板修复上。候选产物位于 `outputs/llm_wiki/`，未 promoted 为稳定产品。

## 如何触发 v3

下一版需要同时解决吞吐、相似卡比较和融合：先允许草稿快速生长，再把比较与审计变成稳定的收敛过程。
