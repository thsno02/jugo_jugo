# v5：按来源类型路由，并治理规模化知识图

## 版本核心

v5 面对的已不是“能不能生产卡片”，而是不同来源如何进入不同阅读面，以及数百张卡片怎样保持证据边界、YAML 稳定和知识图完整性。

## 相对 v4 的优化

- source router 取代扁平 fallback，按 arXiv、webpage、GitHub repo、Reddit 等类型选择材料文件。
- card schema 增加 `evidence_basis`，reframing 必须保留原始 hedge。
- extraction 完成后顺序执行 fusion scan，避免与并行写卡互相污染。
- anti-merge bias 优先保留可链接的差异，避免过度合并破坏原子性与追踪。
- YAML parser / lint 取代正则式 frontmatter 写入。
- backlink、orphan governance 和 backward backlink 成为独立 pass。
- FSJS 按 source type 分片，并区分 grep-verified 与 semantic-verified。

## 关键决策

来源类型决定可读取的 evidence surface；证据基础决定卡片可以采用多强的陈述。图治理不再依赖 LLM 逐卡手改，而由脚本执行双向、幂等的 metadata 更新。

## 实际动作

63 个有效来源按 token 量分成 4 waves 并行提取，生成 487 张 drafts；fusion scan 对 163 对候选进行判断，9 对 duplicate、1 对 merge、153 对 distinct link，最终形成 477 张 active cards。之后补建 151 对链接、治理 81 张孤儿卡并写入 423 条反向链接。

## 结果

- 477 张 active cards。
- 63 个有效来源。
- orphan rate 从 v4 的 6.8% 降到 0%。
- backlink asymmetry 从 40.3% 降到约 0.5%。
- 431 条脚注中 413 条 grep verified；18 条 suspect 经语义审计全部通过。

## 冲突与遗留问题

execution summary 先列出 11 个死源，随后又修正为实际 10 个；两条记录都应保留。repo 来源仍主要只读 README，信息密度偏低。79.8% 零限定词不能直接解释为 hedge 丢失，因为大多数来源本身使用断言体；v6 需要改为条件化 hedge preservation 指标。
