# v3：让知识卡生产进入 draft-first 循环

## 版本核心

v3 把吞吐作为一等问题：先形成可审查草稿，再通过全文阅读、相似卡比较、comparison provenance、融合门禁和统一引用完成收敛。

## 它从哪里开始

v3 不是从 Claude Code 的 `V3 Loop Start Prompt` 突然开始的。它的前置信息来自同一条 Codex 主链中的 v2 性能复盘：7 小时只得到 15 张卡，用户随后提出 draft-first、相似卡比较、信息密度、标签和时间字段等要求。这些讨论先形成 v3 的设计约束。

2026-05-25 12:52，用户明确说“我们现在要开 v3 了”。后续交互建立 v3 scaffold、补齐合同与 handoff，并在 Codex 的最后一条交互中生成 `V3 Loop Start Prompt`。Claude Code 在 13:34 接收该 prompt，才进入版本执行。因此回放按以下阶段展示：

```text
前置决策（precursor）→ 启动交接（handoff）→ 版本执行（execution）→ 转出与复盘（retrospective）
```

## 相对 v2 的优化

- 保留 scoped card 与 provenance gate。
- 采用 draft-first，减少每张卡都经过重型串行控制面的等待。
- 使用 Jieba/Jaccard 取标题相似度 Top-3，并回答比较三问。
- 增加 publication / fusion gate，明确采纳、融合或保留差异。
- 正文统一为 footnote-style citation；`related` 从 footnotes 派生，不再并行维护。
- 中文成为主要阅读和写作语言，避免只读摘要或截断内容。

## 关键决策

相似不等于重复。系统必须把候选卡和最相近的卡放在一起比较，再决定融合或保留；对于引用，一句话可以由多个 raw source 或 knowledge card 支撑，因此 footnote 比单个 inline link 更适合成为引用事实源。

## 实际动作

批量生产草稿，执行相似度检索、comparison provenance、审计和融合；随后把 References / Footnotes / related 的多套机制收敛为统一 citation graph，并通过脚本派生 metadata。

## 结果

约 171 张卡片进入 accepted 状态。这个数字证明 draft-first 可以形成规模，但不能单独证明来源穷尽、知识图质量或后续版本可复现。

执行之后还有两类不能丢失的记录：一类是 architecture / problem / RAG / graph 等真实查询探测；另一类是用户对 LLM Wiki 定义、DIKW、Graphify / GraphRAG 和 presentation 叙事的重新表达。它们解释了用户如何验证和理解 v3，但不应被排在版本执行之前。

## 如何触发 v4

v3 仍然从既定生产管线出发。下一版改用 questioner / reader 独立从 0→1 读取同类材料，验证“问题驱动的穷尽”是否能减少结构先验和遗漏。
