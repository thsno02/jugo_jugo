# LLM Wiki：从机制实验到持续知识生产

这份回忆档案（Recall Archive）回答的不是“仓库里有什么”，而是“这些东西为什么会长出来”。

LLM Wiki 的演化并非一次性设计。它从 v0 的文件系统机制验证出发，经过 v1 的主题枢纽、v2 的原子知识卡、v3 的高吞吐生产、v4 的提问式独立构建，最终在 v5 进入来源路由和规模化治理。每次迭代都保留上一版有效的机制，同时暴露新的生产瓶颈。

## 阅读模型

每个版本都按同一条回忆路径组织：

```text
触发问题 → 用户判断 → 关键决策 → 执行动作 → 可验证产物 → 下一版本触发条件
```

聊天记录提供“为什么”，仓库文件提供“做出了什么”，Git 历史提供“何时进入版本控制”。三者的时间不能互相替代。

## 版本边界

- v0 是序章（Prologue）：机制跑通，但 topic 选错。
- v1-v5 是主版本（Main Versions）。
- v4 是独立的 0→1 构建，不应描述成继承 v3 知识库后继续追加。
- 版本首次进入 Git 的时间不等于设计诞生时间；v0、v1、v2 是在 capsule 迁移时一起加入 Git。

## 公开边界

本地档案可以保留经确认的人类输入全文。公开 HTML 只读取经过隐私审阅的事件；原始 Codex / Claude Code session JSONL 永远保持 local-only。
