# 建立循环控制面

## 背景

当前 LLM Wiki 需要从 0 到 1 持续生长。此前的问题之一是循环规则分散在聊天上下文、README、技能和临时报告中，导致主控 agent 和执行者边界不清。

## 证据

- `llm_wiki/` 只有 README 和 skills，没有专门保存循环状态、任务包、执行者边界和恢复入口的目录。
- 当前任务需要长期自治，人类可能离开电脑，不能依赖聊天记忆恢复。
- 用户明确指出 sub-agent 行为和 scope 没有约定。

## 决策

建立 `llm_wiki/loop/` 作为循环控制面。

主控 agent 负责决策、派发、审计和状态迁移；执行者只在任务包中完成有界工作。

## 不做什么

- 不把 `loop/` 做成隐藏目录。
- 不在 `loop/` 中沉淀最终知识卡。
- 不启动枢纽页、聚类或主题覆盖。
- 不让执行者依赖父聊天上下文。
