# LLM Wiki 知识卡草稿

## 目标

把一个事实候选写成一张原子事实知识卡。知识卡是结果，出处论证是可读的说明文档。两者都应以中文为主语言。

## 原子事实知识卡最小契约

```yaml
statement: <一句可独立阅读的事实陈述>
fact_type: known_fact | accepted_fact
support:
  - <来源定位>
scope: <成立范围>
status: draft
```

## 知识卡写作要求

- 标题直接表达主要事实。
- 正文只围绕一个主要事实展开。
- 解释要短，避免写成报告。
- 不写生产日志、审计过程、任务包内容或控制器推理。
- 可以有轻量链接、引用区（`References`）和脚注区（`Footnotes`）。
- 引用区（`References`）必须放在脚注区（`Footnotes`）前面。
- 脚注区（`Footnotes`）必须是最后一个一级章节。

## 出处论证写作要求

出处论证不是流水日志。它要说明这张知识卡为什么可以暂时被当作事实：

- 事实陈述从哪个来源来。
- 来源的适用性是什么。
- 来源明说了什么。
- 知识卡做了哪些整理或概括。
- 适用范围为什么这样限定。
- 是否有冲突证据或待检索内容。
- 为什么当前状态仍是 `draft`。

## 工作流

1. 读取一个事实候选和它的主来源。
2. 判断事实候选是否真的足够原子化；不够则输出 `LOOP_BLOCKED` 或拆分建议。
3. 写 `card.md`。
4. 写出处论证文件 `provenance.md`。
5. 写 `loop_delivery.md`，列出实际读取的输入、写入文件和未解决问题。

## 禁止事项

- 不合并多个事实候选。
- 不为了完整性扩写成主题摘要。
- 不新增来源没有支撑的主张。
- 不把出处论证塞进知识卡正文。
