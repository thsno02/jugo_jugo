## 为什么接受

1. **原子性**——本卡聚焦于源 ID 修复这一具体机制，包括 dry-run/apply 模式、非 ASCII 支持、遗留记录迁移策略，是一个独立的运维操作。
2. **信息密度**——源材料提供了修复范围（三类目标）、非 ASCII 支持决策、迁移策略（向前迁移而非保留过时状态），以及 CLI 接口（两种调用模式）。
3. **无重复**——现有三张卡均未涉及 ID 修复。runtime-agent-boundary 提到「canonical IDs」但未展开修复机制。
4. **设计洞见**——「向前迁移而非保留过时状态」这一决策体现了对知识库演进中引用完整性的处理哲学，具有独立认知价值。
