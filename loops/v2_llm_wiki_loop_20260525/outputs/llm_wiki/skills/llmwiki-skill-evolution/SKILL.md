# LLM Wiki 技能进化

## 目标

当循环出现偏差时，先修技能和流程，再继续生产 KB。技能进化的目标是让下一轮执行者更少依赖聊天上下文，更少漂移，更能产出中文、可读、可追溯的原子事实知识卡。

## 触发条件

- 文档主语言偏离中文。
- 执行者生成主题、枢纽页或节点，而不是原子事实知识卡。
- 知识卡像中间产物或报告。
- 出处论证变成流水日志。
- 任务包过宽、过重或不可从磁盘复现。
- 主控 agent 开始做具体执行。
- 旧版 v1 的节点/主题技能被误用。

## 工作流

1. 读取失败样本、审计发现和相关技能。
2. 只定位可证实的问题，不把猜测写成结论。
3. 判断是技能措辞、任务包、schema、门禁还是角色边界导致问题。
4. 对技能做最小修订。
5. 保持中文主语言。
6. 保持 schema 简单，避免一开始加入复杂元数据。
7. 写清楚修订原因和后续验证点。

## 修订原则

- 优先减少步骤，而不是增加流程。
- 优先强化边界，而不是增加抽象。
- 优先让执行者读来源并产出小事实。
- 不把枢纽页、聚类、主题覆盖提前带回当前循环。
- 只有当循环反复证明需要时，才新增字段或技能。

## 输出

- 修改后的 `SKILL.md` 或相关任务模板。
- `skill_revision_note.md`：中文记录问题、证据、修改和预期效果。
- 如需进一步验证，派发独立执行者做前向测试；不要把预期答案泄漏给它。
