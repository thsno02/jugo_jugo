# 上下文隔离设计

上下文隔离的目标不是让执行者“更聪明”，而是让执行者无法轻易把父聊天上下文、历史偏差和未授权材料带进产物。

## 隔离层级

### 第 1 层：角色隔离

执行者只接收：

```text
system_prompts/base_worker.md
system_prompts/<role>.md
iterations/<iteration_id>/task.md
```

默认不 fork 父聊天上下文。

### 第 2 层：输入隔离

`task.md` 必须列出允许输入。

执行者可以读取：

- 当前任务包。
- 当前任务包明确列出的来源、候选、草稿卡、出处论证或审计报告。
- 当前任务包明确列出的控制文件。

执行者不可以读取：

- 父聊天上下文。
- `loops/`。
- 旧审计报告。
- 其它执行者产物。
- 未列出的来源目录。

例外必须先写入 `read_log.md`。

### 第 3 层：写入隔离

`task.md` 必须列出允许写入。

执行者只写：

- 当前 iteration 目录。
- 当前 iteration 的 `artifacts/`。
- 任务包明确授权的 KB 产物路径。

### 第 4 层：交付隔离

执行者结束前必须留下：

- `loop_status.md`
- `loop_delivery.md`
- `read_log.md`

没有这些文件，主控 agent 不能验收。

### 第 5 层：审计隔离

`independent_evaluator` 默认只读目标任务包和目标产物，不读父聊天上下文，也不先读已有同类审计报告。

审计报告必须先列证据，再给假设，再用证据验证。

## 主控 agent 的隔离

主控 agent 只能读恢复入口和必要的任务包文件。

主控 agent 不应该把自己在聊天中知道的事实直接写入知识卡或出处论证。聊天只能影响控制决策，不能成为事实来源。

## 失败处理

出现以下情况时，停止生产，进入流程修复：

- 执行者读取了未授权输入且没有记录。
- 执行者写入了未授权路径。
- 执行者输出依赖父聊天上下文。
- 主控 agent 亲自补写了执行者产物。
- 审计者先读了已有审计报告再形成结论。
