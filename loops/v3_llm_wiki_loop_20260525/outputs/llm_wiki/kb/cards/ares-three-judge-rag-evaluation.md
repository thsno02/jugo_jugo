ARES（Automated RAG Evaluation System）不把"RAG 好不好"压成单一分数，而是为同一条 query–document–answer 三元组训练三个独立的二分类判官，每个判官只回答一个问题：

- **Context Relevance（C.R.）**：检索到的 passage 是否对回答这条 query 有用？
- **Answer Faithfulness（A.F.）**：生成的回答是否完全建立在检索到的 passage 之上，没有幻觉或外推？
- **Answer Relevance（A.R.）**：生成的回答相对于 query + 检索到的 passage 是否真的解答了问题？

三个维度对应 RAG 管线里的三段失败模式：检索段（C.R. 低）、生成段对 context 的忠实度（A.F. 低）、生成段对 query 的相关性（A.R. 低）。论文原文把分离判官的动机写得很直白：`"ARES is the first automated RAG evaluation system to generate tailored LLM judges for each component of a RAG pipeline"`。这样定位故障源比单一分数有用得多——同一个 RAG 系统在 NQ 上 C.R.=85.6%、A.R.=93.3%（见 `tab:ares_real_systems`），如果只看一个综合数字，无法判断要去优化检索器还是生成器。

操作含义：

- 每个判官是一个独立 fine-tuned 的 DeBERTa-v3-Large，输入是拼接后的 query–passage–answer 三元组，输出二分类标签。三个判官**不共享参数**。
- A.F. 只在有 attribution 标签的数据集上训练（论文里在 AIS 上做了实验，KILT/SuperGLUE 部分因为没有 hallucinated answer 标签而跳过）。
- 三个判官各自有自己的合成训练数据和 human preference 验证子集；后者会被 PPI 复用做置信区间。

边界：

- 当 RAG 任务发生剧烈领域漂移（英→其它语言、文本→代码、文本→实体抽取）时，三个判官的 Kendall's τ 会显著掉到 0.28–0.38（见 `tab:cross_domain` 之后的实验段落）。每次新领域都需要新的 in-domain passages + few-shot 查询样本来重新配置判官。
