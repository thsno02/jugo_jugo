PoisonedRAG 把现有 LLM/RAG 防御逐一搬过来打了一遍，结论是四类都不行。把每一类**为什么不行**记下来比"它们都不行"本身更有价值——这些失败模式会帮你判断手头的防御设计是否有同样漏洞。

**1. Paraphrasing（改写问题）**：在检索前用 LLM 把目标问题 Q 改写 5 种，再各自检索 + 生成。直觉是改写后 Q 的字面表达变化，黑盒下 `S = Q` 拼出的恶意文本就不再"显眼"。实际：

| Dataset | ASR w/o | ASR w/ paraphrase |
| --- | --- | --- |
| NQ 黑盒 | 0.97 | **0.87** |
| HotpotQA 黑盒 | 0.99 | **0.93** |
| MS-MARCO 黑盒 | 0.91 | **0.79** |

ASR 只降 5–12 个点，依然远高于实用阈值。原因是 retriever 的语义相似度对"问题改写"本就鲁棒——它必须鲁棒，否则 RAG 自身就不工作了。这暴露一个普遍模式：**任何依赖"打乱表面 token"的防御，在能力强的 retriever 面前都接近无效**。

**2. Perplexity-based detection（PPL 检测）**：直觉是恶意文本质量低 → PPL 高。实际 ROC AUC 接近无意义：黑盒下恶意文本由 GPT-4 生成（I 段）+ 原问题 Q（S 段）拼接，质量完全正常；白盒下虽然 S 段是对抗优化出来的"垃圾字符串"，PPL 略高但和 clean text 分布重叠太多。论文原话：「the perplexity values of malicious texts are not statistically higher than those of clean texts」[^1]。把"用 LLM 生成攻击内容"和"内容质量检测"放在一起，本质上是用一个 LLM 去检测另一个 LLM 的输出，先天不利。

**3. Duplicate text filtering（去重）**：直觉是同一目标问题的 N 条恶意文本可能重复 → 哈希去重把它们筛掉。实际 ASR 在三个数据集上**不变**（NQ 0.97 → 0.97 等）。原因是 I 段每次都让 LLM 重新生成、有 temperature，相同 prompt 也产生不同文本；攻击者可以零成本生成完全不重复的恶意文本批次。这告诉我们 **dedup 类防御只能挡住"懒惰攻击者"**。

**4. Knowledge expansion（扩大 k）**：直觉是把 top-k 从 5 拉到 50，clean text 多了就能稀释恶意。实际即使 k=50，HotpotQA 上 ASR 仍有 41% / 43%（黑/白盒）；而且只要攻击者把 N 也同步增大，ASR 反而**回升**。代价侧：长 context → LLM 推理变贵变慢。这意味着"靠多投票/多上下文"对 PoisonedRAG 既不够鲁棒、又同时损失系统效率。

把四种失败放在一起看，可以读出三条"防御设计原则"：

1. **不要在 retriever 层面治这件事**：retriever 越强，恶意文本越容易钻进去；这是个相似度度量的本质问题。
2. **不要赌"内容质量"信号**：恶意 I 段就是 GPT-4 写的，PPL/语法/连贯性都正常。
3. **不要靠 top-k 多数投票**：攻击者可以等量增加 N，让 top-k 里恶意占比保持。

论文给出的工程含义：现有防御不足以挡住 PoisonedRAG，需要**新的**防御机制——例如基于来源信任度、写入审计、跨问答一致性等不属于"检索分数 + 文本统计"框架内的方法（论文未实现，但作为开放方向）。
