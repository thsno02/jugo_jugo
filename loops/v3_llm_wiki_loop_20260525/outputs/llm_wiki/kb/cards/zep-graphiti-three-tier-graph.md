Zep 的核心组件 Graphiti 把 agent 记忆建模成一张分层时序知识图 $\mathcal{G}=(\mathcal{N}, \mathcal{E}, \phi)$，并明确切成三层子图，每层承担不同抽象层级的责任：

- **情节子图 $\mathcal{G}_e$**：节点是 episode（message/text/JSON 原文），充当"非有损"原始事实库；边把 episode 连到它派生出来的语义实体。所有更高层的实体与事实都能逆向追踪到这层做引用/引证。
- **语义实体子图 $\mathcal{G}_s$**：节点是从 episode 中抽取并消歧后的实体（包括说话者本身），边是实体之间的事实/关系，且**支持同一事实在不同实体对间被多次抽取**——以此实现 hyper-edge 风格的多实体事实。
- **社区子图 $\mathcal{G}_c$**：节点是强连通实体簇的社区摘要，借鉴自 GraphRAG，但用 label propagation 替代 Leiden，因为前者天然支持"新节点加入即按邻居多数派归入社区"的增量更新，可以延迟整库 refresh。

这种"原始 episode + 派生语义"的双重存储是有意呼应人类记忆心理学模型中 episodic memory 与 semantic memory 的区分（论文引 gonzalez），不是单纯的工程抽象。它带来几个直接的能力：
1. 任何抽取出的实体/事实都能 cite 回它的来源 episode；
2. episode 反向能拉出相关实体做上下文回填；
3. 社区层提供 domain-level 全局视图，使检索不止能"找到事实"，还能"定位到话题簇"。

边界与误用：community 的增量更新会逐步偏离一次完整 label propagation 的结果，因此**社区是近似启发，必须周期性刷新**，否则随时间漂移。论文也提示该方案目前不依赖正式 ontology，对强 schema 场景仍是开放问题。
