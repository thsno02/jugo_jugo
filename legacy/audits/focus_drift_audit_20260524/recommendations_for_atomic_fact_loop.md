# 原子事实循环建议

`status`: `LOOP_DONE`

## 最小方向

下一版只做一件事：生长原子事实知识卡。当前循环不做枢纽页、主题、聚类、覆盖骨架，也不把论文或网页先压成主题报告。

合格产物是：

- 一个清晰可读的原子事实知识卡。
- 一个可读的出处论证文档，说明为什么这张知识卡可以被暂时当作事实。
- 一个最小状态记录，说明它是 `draft`、`accepted` 还是 `rejected`。

## 最小结构契约

知识卡的最小契约保持简单：

```yaml
statement: <一句可独立阅读的事实陈述>
fact_type: known_fact | accepted_fact
support:
  - <来源定位>
scope: <适用范围>
status: draft | accepted | rejected
```

说明：

- `known_fact` 指高度稳定、近似不变的事实。
- `accepted_fact` 指在某个社区、版本、流程或上下文中目前被接受的事实。
- 原子是相对概念，不是绝对真理。它只表示当前知识卡的粒度足够小、足够清楚、足够可被出处论证支持。

## 知识卡可读性契约

知识卡是结果，不是过程日志。它应该像 zet 风格知识卡一样可读：

- 标题直接表达事实。
- 正文先给事实陈述，再给少量解释。
- 不塞入长篇流程、审计痕迹或控制器推理。
- 引用和脚注可以存在，但不能破坏阅读。
- 引用区（`References`）放在脚注区（`Footnotes`）前面。
- 脚注区（`Footnotes`）必须是最后一个一级章节。

## 出处论证是可读文档

出处论证不是杂乱日志，也不是事后挑战。它是整理后的可读文档，用来说明知识卡为什么能暂时成立。

出处论证至少回答：

- 这个事实陈述来自哪些来源。
- 来源的权威性或适用性是什么。
- 事实陈述的适用范围为什么这样限定。
- 是否有冲突证据或不确定性。
- 为什么状态是 `draft`、`accepted` 或 `rejected`。
- 与其他知识卡的关系是什么。

## 替换门禁

旧门禁：

- 节点版本束完整性。
- 引用图刷新。
- 采纳视图。
- 主题覆盖。

新门禁：

- 事实陈述是否单一。
- 事实陈述是否可独立阅读。
- 证据是否直接支撑事实陈述。
- 事实类型是否合理。
- 适用范围是否明确。
- 出处论证是否可读且足以说明成立理由。
- 知识卡是否没有混入枢纽页或主题综合。

## 替换指标

不要再用主题覆盖作为当前阶段指标。改用：

- `fact_candidates_mined`
- `cards_drafted`
- `cards_accepted`
- `cards_rejected`
- `cards_deferred`
- `provenance_pass_rate`
- `scope_revision_count`
- `source_access_deferred`

这些指标服务于扎实基础，而不是服务于“看起来覆盖了一张主题图”。

## 来源挖掘任务包模板

```text
Task: 从一个来源中抽取 5-10 个原子事实候选。

Allowed input:
- 仅指定来源。
- 已有知识卡只能用于避免重复，不能作为事实支持。

Output:
- fact_candidates.yaml
- source_notes.md
- loop_status.md
- loop_delivery.md

禁止:
- 生成主题节点。
- 生成枢纽页。
- 合成覆盖计划。
- 把多个事实压成一个知识卡。
```

## 知识卡草稿任务包模板

```text
Task: 将 exactly one 事实候选写成 one 原子事实知识卡。

Allowed input:
- 事实候选。
- 原始来源。
- 必要的相邻知识卡，只用于链接边界。

Output:
- card.md
- provenance.md
- loop_status.md
- loop_delivery.md

禁止:
- 添加未由来源支持的新主张。
- 写枢纽页或主题摘要。
- 把出处论证写成原始日志。
```

## 旧版 v1 设计如何重新进入

旧版的主题计划、枢纽页、聚类、视图构建、影响图并非永远不用。它们应该在原子事实基础足够稳定后重新进入：

1. 先积累已采纳原子事实知识卡。
2. 再从知识卡的链接、出处论证和来源关系中发现聚类。
3. 再让枢纽页和主题从聚类中生长。
4. 最后再做覆盖和视图。

当前不要提前做第 2-4 步。

## 最小下一步

建立一个全新的 active `llm_wiki/` 结构，只包含原子事实循环所需目录和契约。先选一个来源，派发来源挖掘执行者抽取事实候选，再逐个写知识卡、出处论证和审计。主控 agent 只做决策与派发，不直接执行具体内容生产。
